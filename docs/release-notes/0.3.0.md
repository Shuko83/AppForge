*Version française [plus bas](#français).*

AppForge 0.3.0 lets an application keep what its user chooses from one run to the next, finds plugins in several directories, and gives Forge a face of its own.

## What is new

**Settings files**, a new `Settings` module in Core:

- An application keeps in settings files the values its user gives some properties, the profile they chose, say, and finds them again the next time it runs; the value the project gives such a property becomes its default value.
- `ForgeApplication` owns them and saves them in the project. `start()` reads each file before any component is initialized, writes the values of the project to a file that does not exist yet, and sets aside, as `.bak`, a file that cannot be read; what changes these properties while the application runs is written to their files, and `stop()` gives them back their default values. What else a file holds is kept.
- In Forge, **Add settings file** adds one to the edition zone and opens its dialog: the name of its file, its directory, and the properties of the instances and of their objects to check. Dashed lines join it to the instances whose properties it holds, **Write default values** writes the values of the project to it, and the properties it holds are in italics in the property editor.
- The `ProfileSelector` component of `ExternalPlugin` shows it: the profile chosen is the one shown the next time.

**Plugin directories on the command line:**

- `--plugin-dir <directory>`, as many times as needed, scans each directory after `plugins/`, in their order. `ForgeApplication::addCommandLineOptions()` adds it, with `--plugin-root`, to a `QCommandLineParser`, and `applyCommandLine()` applies them: Forge, `ExampleForgeApp` and the `main` of any application can take them.
- A plugin of a project is looked for by its id among the plugins found, its file being only a last resort: a project opens wherever its plugins are.

**Forge:**

- A splash screen with the version of the framework, of Qt and of the compiler, the date of the build and the license.
- A logo, the icon of its windows and of `Forge.exe`.
- A search bar above the list of components (Ctrl+F), on their name, their description or their category.
- An instance dropped while the application runs can be started on its own, with **Start component** in its context menu, and **Start** starts all those that do not run yet.

**Fixed:** the context menu of a component no longer offers to add a zone under it.

## Upgrading from 0.2.0

- Build your plugins again against 0.3.0.
- A project of 0.2.0 opens as it is; a project of 0.3.0 with settings files loses them when it is opened and saved by Forge 0.2.0.
- `find_package(AppForge 0.3 REQUIRED COMPONENTS Core)` to require this version.

## The package of this release

`AppForge-0.3.0-win64-msvc2022-qt6.8.zip` is built for Windows x64 with MSVC 2022 and Qt 6.8, in `Release` only.

- **To try Forge:** unzip and run `Forge/Release/bin/Forge.exe`. Qt and the example plugin are next to it.
- **To build a plugin:** point `CMAKE_PREFIX_PATH` at the unzipped folder, as the README shows in *Building a plugin outside AppForge*. Build it in `Release`, with MSVC 2022 and Qt 6.8: Qt does not load a `Debug` plugin into a `Release` application.
- **For any other setup**, `Debug` included, build AppForge from its sources: CMake 3.19 or later, Qt 6 (Core and Widgets) and a compiler with C++20 concepts and ranges. Clone with `--recurse-submodules`.

## Known limits

- Built and tested on Windows with MSVC only.
- A plugin has to be built again for each version of AppForge: the layout of the classes it derives from may change, and the check made when a plugin is found only compares versions.
- An unloaded plugin keeps its file in use until the application exits: a plugin built again is only read at the next start.
- In Forge, a link is only removed with one of its components or replaced by another one; nothing is undone; and the application can still be edited while it runs.
- A settings file keeps the values of the user under the names of the instances: renaming an instance leaves them under its former name. Run from Forge, a settings file without a directory is written to the configuration directory of Forge, not to that of the application delivered.
- No automated tests yet.

## Français

AppForge 0.3.0 permet à une application de garder d'un lancement à l'autre ce que son utilisateur choisit, trouve des plugins dans plusieurs dossiers, et donne à Forge un visage à lui.

## Les nouveautés

**Fichiers de réglages**, un nouveau module `Settings` dans Core :

- Une application garde dans des fichiers de réglages les valeurs que son utilisateur donne à certaines propriétés, le profil qu'il a choisi par exemple, et les retrouve au lancement suivant ; la valeur que le projet donne à une telle propriété devient sa valeur par défaut.
- `ForgeApplication` les possède et les enregistre dans le projet. `start()` lit chaque fichier avant qu'aucun composant ne soit initialisé, écrit les valeurs du projet dans un fichier qui n'existe pas encore, et met de côté, en `.bak`, un fichier illisible ; ce qui change ces propriétés pendant l'exécution est écrit dans leurs fichiers, et `stop()` leur rend leurs valeurs par défaut. Le reste du contenu d'un fichier est conservé.
- Dans Forge, **Add settings file** en ajoute un dans la zone d'édition et ouvre sa fenêtre : nom du fichier, dossier, et propriétés des instances et de leurs objets à cocher. Des traits pointillés le relient aux instances dont il tient des propriétés, **Write default values** y écrit les valeurs du projet, et les propriétés qu'il tient sont en italique dans l'éditeur de propriétés.
- Le composant `ProfileSelector` d'`ExternalPlugin` le montre : le profil choisi est celui affiché au lancement suivant.

**Dossiers de plugins en ligne de commande :**

- `--plugin-dir <dossier>`, autant de fois que nécessaire, scanne chaque dossier après `plugins/`, dans l'ordre donné. `ForgeApplication::addCommandLineOptions()` l'ajoute, avec `--plugin-root`, à un `QCommandLineParser`, et `applyCommandLine()` les applique : Forge, `ExampleForgeApp` et le `main` de toute application peuvent les prendre.
- Un plugin d'un projet est cherché par son id parmi les plugins trouvés, son fichier n'étant qu'un recours : un projet s'ouvre là où sont ses plugins.

**Forge :**

- Un écran de démarrage avec la version du framework, de Qt et du compilateur, la date de compilation et la licence.
- Un logo, icône de ses fenêtres et de `Forge.exe`.
- Une barre de recherche au-dessus de la liste des composants (Ctrl+F), sur leur nom, leur description ou leur catégorie.
- Une instance déposée pendant l'exécution peut être démarrée seule, par **Start component** dans son menu contextuel, et **Start** démarre toutes celles qui ne tournent pas encore.

**Corrigé :** le menu contextuel d'un composant ne propose plus d'ajouter une zone sous lui.

## Passer de la 0.2.0 à la 0.3.0

- Recompiler ses plugins avec la 0.3.0.
- Un projet de la 0.2.0 s'ouvre tel quel ; un projet de la 0.3.0 qui a des fichiers de réglages les perd s'il est ouvert puis enregistré par Forge 0.2.0.
- `find_package(AppForge 0.3 REQUIRED COMPONENTS Core)` pour exiger cette version.

## Le paquet de cette version

`AppForge-0.3.0-win64-msvc2022-qt6.8.zip` est compilé pour Windows x64 avec MSVC 2022 et Qt 6.8, en `Release` seulement.

- **Pour essayer Forge :** décompresser et lancer `Forge/Release/bin/Forge.exe`. Qt et le plugin d'exemple sont à côté.
- **Pour construire un plugin :** pointer `CMAKE_PREFIX_PATH` sur le dossier décompressé, comme le montre le README dans *Building a plugin outside AppForge*. Le compiler en `Release`, avec MSVC 2022 et Qt 6.8 : Qt ne charge pas un plugin `Debug` dans une application `Release`.
- **Pour toute autre configuration**, `Debug` compris, compiler AppForge depuis ses sources : CMake 3.19 ou plus récent, Qt 6 (Core et Widgets) et un compilateur qui connaît les concepts et les ranges de C++20. Cloner avec `--recurse-submodules`.

## Limites connues

- Compilé et testé sous Windows avec MSVC uniquement.
- Un plugin est à recompiler pour chaque version d'AppForge : l'agencement des classes dont il dérive peut changer, et le contrôle fait quand un plugin est trouvé ne compare que des versions.
- Un plugin déchargé garde son fichier ouvert jusqu'à la fermeture de l'application : un plugin recompilé n'est relu qu'au lancement suivant.
- Dans Forge, un lien ne part qu'avec l'un de ses composants ou remplacé par un autre ; rien ne s'annule ; et l'application reste modifiable pendant qu'elle tourne.
- Un fichier de réglages range les valeurs de l'utilisateur sous le nom des instances : renommer une instance les laisse sous son ancien nom. Lancé depuis Forge, un fichier de réglages sans dossier est écrit dans le dossier de configuration de Forge, pas dans celui de l'application livrée.
- Pas encore de tests automatisés.
