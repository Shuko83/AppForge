First published version of AppForge, a C++ and Qt 6 framework to build applications by assembling components that plugins provide. It comes with Forge, the editor that assembles them, and with what a project of its own needs to build plugins against it.

## What is in it

**Core**, the library applications and plugins link to:

- **Plugins.** `appforge_add_plugin()` builds one in a single CMake call. Its id, name, description and versions are embedded in its file and read without loading it. `PluginManager` finds the plugins next to an application, loads them, and unloads them.
- **Components.** A plugin declares them and builds each with the class holding its logic; `ComponentFactory` is the only way to create one. A component is configured through its `Q_PROPERTY` and goes from `Initializing` to `Ready` to `Running`.
- **Interfaces.** A component declares what it provides and what it consumes, by name and type; `bindInterface()` binds a consumer to a provider of the same type.
- **Properties of inner objects.** `addPropertiesForQObject()` exposes the properties of an object a component is made of, a widget say, next to its own.
- **Applications.** `ForgeApplication` opens a project, instantiates its components, binds them and runs them: it is all the `main` of an application has to do.

**Forge**, the editor:

- Lists the plugins and their components; loads, unloads and opens plugins from anywhere on the disk.
- An edition zone where components are dropped to be instantiated, then moved, renamed, colored, removed, and bound by drawing links between their interfaces.
- Colored, titled zones to group instances.
- An editor for the properties of the selected instance: texts, numbers, booleans and dates.
- **Run**: starts and stops the assembled application in place, with the state of each instance shown on it.
- Projects saved to and opened from `.afp` files, a JSON format described in the README.

**Package for other projects:**

- `find_package(AppForge 0.2 REQUIRED COMPONENTS Core)` gives `AppForge::Core` and `appforge_add_plugin()`, with the CMake files it needs: nothing else to include.

**Examples:** `ExamplePlugin` and `ExternalPlugin` (the `Greeter`, `Ticker` and `Window` components), `ExampleApp`, and `ExampleForgeApp`, which runs a project saved by Forge.

## The package of this release

`AppForge-0.2.0-win64-msvc2022-qt6.8.zip` is built for Windows x64 with MSVC 2022 and Qt 6.8, in `Release` only.

- **To try Forge:** unzip and run `Forge/Release/bin/Forge.exe`. Qt and the example plugin are next to it.
- **To build a plugin:** point `CMAKE_PREFIX_PATH` at the unzipped folder, as the README shows in *Building a plugin outside AppForge*. Build it in `Release`, with MSVC 2022 and Qt 6.8: Qt does not load a `Debug` plugin into a `Release` application.
- **For any other setup**, `Debug` included, build AppForge from its sources: CMake 3.19 or later, Qt 6 (Core and Widgets) and a compiler with C++20 concepts and ranges. Clone with `--recurse-submodules`.

## Known limits

- Built and tested on Windows with MSVC only.
- A plugin has to be built again for each version of AppForge: the layout of the classes it derives from may change, and the check made when a plugin is found only compares versions.
- An unloaded plugin keeps its file in use until the application exits: a plugin built again is only read at the next start.
- In Forge, a link is only removed with one of its components or replaced by another one; nothing is undone; and the application can still be edited while it runs.
- No automated tests yet.

## Français

Première version publiée d'AppForge, un framework C++ et Qt 6 pour construire des applications en assemblant des composants fournis par des plugins. Elle vient avec Forge, l'éditeur qui les assemble, et avec ce qu'il faut à un projet tiers pour construire des plugins.

## Ce qu'elle contient

**Core**, la bibliothèque à laquelle se lient applications et plugins :

- **Plugins.** `appforge_add_plugin()` en construit un en un seul appel CMake. Son id, son nom, sa description et ses versions sont inscrits dans son fichier et lus sans le charger. `PluginManager` trouve les plugins à côté d'une application, les charge et les décharge.
- **Composants.** Un plugin les déclare et construit chacun avec la classe qui porte sa logique ; `ComponentFactory` est le seul moyen d'en créer un. Un composant se configure par ses `Q_PROPERTY` et passe de `Initializing` à `Ready` puis `Running`.
- **Interfaces.** Un composant déclare ce qu'il fournit et ce qu'il consomme, par nom et par type ; `bindInterface()` lie un consommateur à un fournisseur du même type.
- **Propriétés des objets internes.** `addPropertiesForQObject()` expose les propriétés d'un objet dont un composant est fait, un widget par exemple, à côté des siennes.
- **Applications.** `ForgeApplication` ouvre un projet, instancie ses composants, les lie et les fait tourner : c'est tout ce que le `main` d'une application a à faire.

**Forge**, l'éditeur :

- Liste les plugins et leurs composants ; charge, décharge et ouvre des plugins depuis n'importe où sur le disque.
- Une zone d'édition où un composant déposé est instancié, puis déplacé, renommé, coloré, supprimé, et lié en traçant des liens entre ses interfaces.
- Des zones colorées et titrées pour regrouper les instances.
- Un éditeur des propriétés de l'instance sélectionnée : textes, nombres, booléens et dates.
- **Run** : démarre et arrête sur place l'application assemblée, l'état de chaque instance étant affiché dessus.
- Des projets enregistrés dans des fichiers `.afp` et rouverts, un format JSON décrit dans le README.

**Paquet pour les autres projets :**

- `find_package(AppForge 0.2 REQUIRED COMPONENTS Core)` donne `AppForge::Core` et `appforge_add_plugin()`, avec les fichiers CMake dont elle a besoin : rien d'autre à inclure.

**Exemples :** `ExamplePlugin` et `ExternalPlugin` (les composants `Greeter`, `Ticker` et `Window`), `ExampleApp`, et `ExampleForgeApp`, qui fait tourner un projet enregistré par Forge.

## Le paquet de cette version

`AppForge-0.2.0-win64-msvc2022-qt6.8.zip` est compilé pour Windows x64 avec MSVC 2022 et Qt 6.8, en `Release` seulement.

- **Pour essayer Forge :** décompresser et lancer `Forge/Release/bin/Forge.exe`. Qt et le plugin d'exemple sont à côté.
- **Pour construire un plugin :** pointer `CMAKE_PREFIX_PATH` sur le dossier décompressé, comme le montre le README dans *Building a plugin outside AppForge*. Le compiler en `Release`, avec MSVC 2022 et Qt 6.8 : Qt ne charge pas un plugin `Debug` dans une application `Release`.
- **Pour toute autre configuration**, `Debug` compris, compiler AppForge depuis ses sources : CMake 3.19 ou plus récent, Qt 6 (Core et Widgets) et un compilateur qui connaît les concepts et les ranges de C++20. Cloner avec `--recurse-submodules`.

## Limites connues

- Compilé et testé sous Windows avec MSVC uniquement.
- Un plugin est à recompiler pour chaque version d'AppForge : l'agencement des classes dont il dérive peut changer, et le contrôle fait quand un plugin est trouvé ne compare que des versions.
- Un plugin déchargé garde son fichier ouvert jusqu'à la fermeture de l'application : un plugin recompilé n'est relu qu'au lancement suivant.
- Dans Forge, un lien ne part qu'avec l'un de ses composants ou remplacé par un autre ; rien ne s'annule ; et l'application reste modifiable pendant qu'elle tourne.
- Pas encore de tests automatisés.
